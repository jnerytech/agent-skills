# Glossary — Kubernetes Secrets Handbook

**aescbc** — AES-CBC encryption provider for `EncryptionConfiguration`; "considered weak but fast" (Ch 3)
**aesgcm** — AES-GCM encryption provider; "faster and less weak **when key rotation is implemented**" (Ch 3, Ch 13)
**Admission controller** — control-plane component intercepting API requests after authn/authz but before persistence; can reject or modify objects (Ch 12)
**Authorization sprawl** — RBAC permissions set too broadly, usually unintentionally; the Kubernetes form of secret access ballooning (Ch 13)
**base64** — the *encoding* (not encryption) applied to `Secret.data` values, for safe transport of special characters (Ch 1, Ch 2)
**Bootstrap token** — Secret type used only during cluster init, to join new nodes (Ch 2)
**Broker** — intermediary that validates a request, fetches the secret, delivers it, and logs the transaction (Ch 12)
**certstrap** — certificate management tool Square used to run its own CAs, avoiding OpenSSL complexity (Ch 13)
**CIS Benchmarks** — per-platform security-control benchmarks mapping onto HIPAA, PCI-DSS, ISO 27000, SOC 2, NIST (Ch 5)
**Citadel** — Istio's CA component: generates, distributes, rotates, and revokes mesh certificates (Ch 12)
**Client (Keywhiz)** — any certificate that gains access to Secrets (Ch 13)
**Cloud KMS** — GCP's key management service; key ring + crypto key (Ch 10)
**CMK (customer-managed key)** — your own KMS key used instead of the provider's default (Ch 10)
**Compliance Operator** — operator running CIS and OpenSCAP profile checks **with remediation** (Ch 5)
**ConfigMap** — object whose `data` takes raw UTF-8 strings; widely misused for sensitive data, so treat it like a Secret (Ch 1)
**container-engine-robot** — the GKE control plane's Google-managed service account, **outside your project**; needs the KMS role (Ch 10)
**CRD (CustomResourceDefinition)** — API extension adding a new object type; **useless without a controller** (Ch 1, Ch 12)
**CSI (Container Storage Interface)** — standardized storage interface; the basis of Secrets Store CSI Driver (Ch 8, Ch 12)
**DaemonSet** — one Pod per node; the CSI driver's deployment shape, and the pattern for node-level Secrets (Ch 8, Ch 12)
**DEK (data encryption key)** — encrypts the payload; generated locally by kube-apiserver (Ch 3)
**destroy (Vault)** — forces physical deletion of a KV-2 secret version; `delete` only marks it (Ch 11)
**Diagnostic settings** — Azure's audit pipeline; routes `AuditEvent` logs to storage, Log Analytics, or Event Hub (Ch 9)
**dm-crypt** — plain device-mapper block encryption; deniable, no key rotation, no TRIM safety (Ch 3)
**DRP (Disaster Recovery Plan)** — roles, communication strategy, incident response, and tested recovery procedures (Ch 6)
**Dry run** — `kubectl --dry-run=client`; validates syntax and type but **not content** (Ch 4)
**Dynamic Secrets** — generated on demand, short TTL, invalidated after use; the fix for secret valet parking (Ch 7, Ch 11)
**EaC (Everything as Code)** — codify infrastructure, application, governance, compliance, security, and the BCP into CI/CD (Ch 14)
**EncryptionConfiguration** — `apiserver.config.k8s.io/v1` object listing resources and an **ordered** provider list (Ch 3)
**Environment controller** — manipulates Pod env vars directly without extending the Kubernetes API (Ch 12)
**etcd** — Kubernetes' key-value asset store; **has no encryption capability of its own** except on the wire (Ch 1, Ch 3)
**etcdctl** — etcd CLI; `ETCDCTL_API=3 etcdctl snapshot save` is the raw backup path (Ch 6)
**ExternalSecret** — canonical CRD shape mapping an external store key to a Pod-facing name (Ch 12)
**FDE / SED** — full-disk / self-encrypting disk; transparent, offloaded, but has documented attacks (Ch 3)
**Federated identity credential** — Azure object linking the AKS OIDC issuer to Azure AD, scoped by `subject` (Ch 9)
**Gameday** — simulated failure exercise; must cover cluster loss, store loss, **and backup-system loss** (Ch 6)
**GitOps** — Git as the single source of desired state; Argo CD reconciles the cluster toward it (Ch 2, Ch 13)
**GKE security posture dashboard** — GCP cluster posture scanning + workload/package vulnerability scanning (Ch 10)
**Group (Keywhiz)** — the tag joining clients to Secrets; shared tag ⇒ access granted (Ch 13)
**Helm Secrets** — Helm plugin encrypting chart values via AWS/GCP KMS or GPG, driven by `.sops.yaml` (Ch 4)
**HKDF** — HMAC-based key derivation function; gives each Keywhiz secret a unique key (Ch 13)
**HSM (hardware security module)** — physical protection for master keys or key shards (Ch 7, Ch 11, Ch 13)
**Identity provider (`identity`)** — the default no-op encryption provider; also the way to revert to plaintext (Ch 3)
**Immutable Secret** — `immutable: true`; **permanently** blocks edits, delete-and-recreate is the only change path (Ch 2)
**Init container** — runs before app containers; fetches Secrets into a shared volume before startup (Ch 12)
**Integrated storage (Vault)** — HashiCorp-maintained Raft storage collocated with the host; no network hops (Ch 11)
**IRSA (IAM Roles for Service Accounts)** — AWS workload identity via OIDC federation and a SA annotation (Ch 8)
**JIT (just-in-time) access** — access granted only for the window it is needed (Ch 7)
**KEK (key encryption key)** — encrypts the DEK; generated and hosted **remotely on the KMS** (Ch 3)
**KEP (Kubernetes Enhancement Proposal)** — how the project documents design changes and target releases (Ch 14)
**KEP-3299** — "KMSv2 Improvements": KMSv1 deprecated in 1.28, KMSv2 GA targeted 1.29, `KMSv2KDF` gate (Ch 14)
**Keyring mode** — rotation method keeping multiple secret versions live to prevent downtime (Ch 13)
**Keysync** — Keywhiz client; mTLS fetch into tmpfs, serves from cache during server outages (Ch 13)
**Keywhiz** — Square's Secrets management system; **deprecated 18 September 2023**, migrate to Vault (Ch 13)
**kms provider** — encryption provider using an external KMS via a plugin and envelope encryption (Ch 3)
**KMS provider plugin** — shim connecting kube-apiserver to a KMS over a **local UNIX socket** (e.g. Trousseau) (Ch 3)
**KMSv1 / KMSv2** — v1: a DEK per Secret, KMS call per transaction. v2: one DEK at startup, cached, partition-tolerant (Ch 3)
**kube-bench** — Aqua Security tool measuring a cluster against the CIS Benchmark; supports `Type: "skip"` (Ch 5)
**kubeseal** — CLI that encrypts a Secret into a `SealedSecret` (Ch 12)
**KV-1 / KV-2** — Vault secrets engines; KV-2 versions Secrets, retaining **10 versions** by default (Ch 11)
**Locked Shields** — international cyber-defence exercise; the model for gamified incident-response drills (Ch 14)
**Long-lived access token** — a service account token materialized as a Secret; automatic pre-v1.27 (Ch 2)
**LUKS** — universal disk encryption with key derivation, rotation, and multiple passphrases (Ch 3)
**Masking** — obscuring secret values in logs and UIs; a speed bump, not a control (Ch 13)
**mTLS** — mutual TLS; both client and server prove identity. Square's and Istio's authentication basis (Ch 12, Ch 13)
**Mutating webhook** — custom code run on resource create/modify; how the Vault Agent Injector works (Ch 11, Ch 12)
**NBDE (network-bound disk encryption)** — quorum of servers (Tang) holding split key material; unlock only on the right network (Ch 3, Ch 14)
**Opaque** — the default Secret type; user-defined `data` shape (Ch 1, Ch 2)
**OpenSCAP** — scans an install base against SCAP profiles, emitting risk-scored audits and remediations (Ch 3, Ch 5)
**Performance standby node** — Vault node serving reads, giving horizontal read scalability (Ch 11)
**PKI** — public key infrastructure; X.509 certificates as service identity (Ch 13)
**Platform Secrets** — Secrets internal Kubernetes components need; **must stay in the cluster** for resilience (Ch 1)
**Private Logs Viewer** — the GCP permission required to read audit logs (Ch 10)
**Raft** — consensus algorithm behind Vault and Conjur HA; tolerates `(n-1)/2` node failures (Ch 11)
**RBAC** — Role + RoleBinding (namespaced), ClusterRole + ClusterRoleBinding (cluster-wide) (Ch 2)
**Restart as reload** — rotation method that restarts Pods on change so init containers re-fetch (Ch 13)
**Root key (Vault)** — generated at init, stored encrypted; decrypted by the unseal key into memory only (Ch 11)
**SealedSecret** — Bitnami one-way-encrypted Secret, safe in Git; decrypts in-cluster into a **normal Secret** (Ch 12)
**Secret** — Kubernetes object storing sensitive key–value pairs, base64-encoded, unencrypted by default (Ch 1)
**Secret access ballooning** — unwarranted expansion of who can reach Secrets; a group of 10 becomes 400 (Ch 7)
**Secret island** — a tool with its own Secrets/access/audit but no interoperability or central policy (Ch 7)
**Secret sprawl** — the same credential scattered across source, config, Git, wikis, Dropbox (Ch 7)
**Secret valet parking** — handing Secrets to a subsystem that fetches them onto a host filesystem (Ch 7)
**Secret zero** — a single master key protecting everything; the "keys to the kingdom" SPOF (Ch 7)
**Secretless broker** — establishes the connection on the app's behalf, **never revealing the secret** (Ch 12)
**SecretProviderClass** — CRD carrying driver config and provider parameters to the Secrets Store CSI Driver (Ch 8–11)
**Secrets Store CSI Driver** — `secrets-store.csi.k8s.io`; CRD + DaemonSet mounting Secrets into **tmpfs** (Ch 8, Ch 12, Ch 14)
**Security posture** (NIST 800-37) — the security status of networks, information, and systems, plus the capability to react as the situation changes (Ch 5)
**Security principal** — an Azure entity with an identity: user, group, or computer account (Ch 9)
**Seal / unseal** — sealing purges Vault's root key from memory, halting operations; unsealing restores it (Ch 11)
**Shamir's Secret Sharing (SSS)** — splits a secret into shares requiring a **threshold** to reconstruct (Ch 7, Ch 11)
**SIEM** — security information and event management; correlates events across systems (Ch 13, Ch 14)
**SIG (Special Interest Group)** — Kubernetes project group; SIG Auth owns KMSv2 (Ch 14)
**SOPS** — Mozilla Secrets OPerationS; encrypts Secrets for Git using cloud KMS or PGP (Ch 2, Ch 4)
**StackRox** — open-source Kubernetes security platform: images, runtime, network flows, regulatory scanning (Ch 5)
**Step-up authentication** — requires authentication at or above the level the resource's policy demands (Ch 7)
**stringData** — Secret field taking plaintext; Kubernetes encodes it. Stored form is still base64 (Ch 2)
**Sync Secret** — CSI Secrets Store feature syncing external Secrets into **native Secret objects** — needs encryption at rest (Ch 14)
**system:auth-delegator** — ClusterRole enabling delegated authn/authz checks; required for Vault's `TokenReview` (Ch 11)
**Tang** — reference NBDE key server (Ch 3)
**Tekton** — open-source framework for building CI/CD systems inside Kubernetes (Ch 13)
**Tier-0 service** — a service whose failure halts everything downstream; Secrets qualify (Ch 6)
**tmpfs** — in-memory filesystem; CSI-mounted Secrets never touch node disks (Ch 12, Ch 13)
**TokenReview** — the Kubernetes API call Vault uses to validate a Pod's ServiceAccount JWT (Ch 11)
**TPM** — Trusted Platform Module; can auto-unlock LUKS at boot (Ch 3, Ch 14)
**Trivy** — Aqua Security scanner with a **Secrets-specific** severity check (Ch 5)
**Trousseau** — KMS provider plugin bridging kube-apiserver to Vault, Azure Key Vault, or AWS KMS (Ch 3)
**Vault Agent Injector** — mutating webhook rewriting Pod specs to add agent containers rendering Secrets to a memory volume (Ch 11)
**Vault Radar** — HashiCorp scanner finding leaked/hardcoded Secrets, ranked by risk (Ch 14)
**Velero** — open-source Kubernetes backup/restore and migration, covering objects and persistent volumes (Ch 6)
**Workload Identity** — machine identity for workloads: GKE (`iam.gke.io/gcp-service-account`), AKS (federated credential), AWS (IRSA) (Ch 8–10)
**Workload Identity Federation** — OIDC trust between a CI/CD provider and a cloud, yielding short-lived credentials (Ch 13)
**WORM** — write-once-read-many storage; with S3 Object Lock, makes backups immutable (Ch 6)
