# Chapter 2: Database (Postgres)

## Core Idea
Supabase is "just Postgres" with batteries: every project is a full Postgres instance where tables, functions, triggers, RLS policies, and extensions are first-class. The product surface (Auth, Storage, Realtime, PostgREST API) is wired into the database via reserved schemas (`auth`, `storage`, `realtime`) and roles (`anon`, `authenticated`, `service_role`). Master SQL and you master Supabase: the API is auto-generated from your schema, and security is enforced in the database via Row Level Security, not the app tier.

## Frameworks Introduced
- **RLS-first authorization**: Enforce access at the row level inside Postgres so every client path (REST, GraphQL, direct SQL) is protected by the same rule.
  - When to use: any table exposed through the auto API and reachable by `anon`/`authenticated`.
  - How: `ALTER TABLE t ENABLE ROW LEVEL SECURITY;` then `CREATE POLICY ... FOR <op> TO <role> USING (...) WITH CHECK (...)`. Reference the JWT via `auth.uid()` / `auth.jwt()`.
- **SECURITY DEFINER + locked search_path**: Run privileged logic safely from low-privilege callers.
  - When to use: a function that must escalate (e.g. read across RLS) but is called by `authenticated`.
  - How: `security definer set search_path = ''` and fully-qualify every object (`public.table`). Never ship a definer function without the empty search_path — it is an injection vector.
- **Generated tsvector + GIN**: Precompute full-text search tokens in a stored column and index it.
  - When to use: text search at scale instead of ad-hoc `to_tsvector(col)` per query.
  - How: `GENERATED ALWAYS AS (to_tsvector('english', body)) STORED` + `USING GIN(col)`.
- **Supavisor pooling by mode**: Pick the connection mode to fit the client lifecycle.
  - When to use: serverless/edge → transaction mode (port 6543); long-lived backends or migrations → session/direct (5432).
  - How: swap the pooler host/port in the connection string.
- **Webhook = trigger over pg_net**: Fire async HTTP on data change without blocking the write.
  - When to use: notify external services / Edge Functions on INSERT/UPDATE/DELETE.
  - How: `AFTER` trigger calling `supabase_functions.http_request(...)`, backed by `pg_net`.

## Key Concepts
- **Schemas**: `public` (your tables), `auth`/`storage`/`realtime` (system), `extensions` (where extensions install), `net` (pg_net). Use a `private` schema for admin-only data.
- **Roles**: `anon` (no JWT), `authenticated` (valid JWT), `service_role` (bypasses RLS), `authenticator` (PostgREST connects, switches role per JWT), plus `supabase_*_admin`.
- **Identity columns**: `generated always as identity` (no override) vs `generated by default as identity` (override allowed) — prefer over `serial`.
- **jsonb vs json**: `jsonb` is binary/decomposed (fast, indexable with GIN); `json` is raw text. Use `jsonb`.
- **Views**: default to SECURITY DEFINER (bypass RLS); add `with(security_invoker=true)` to respect caller's RLS. Materialized views need manual `refresh materialized view`.
- **Publication / replication slot / subscription / LSN**: logical replication primitives; output formats `pgoutput` (default) or `wal2json`.
- **EXPLAIN ANALYZE**: shows the actual plan + timing; the tool for diagnosing missing indexes and slow RLS.
- **pg_stat_statements**: aggregate query stats (`calls`, `mean_exec_time`, `total_exec_time`) to find expensive queries.

## Mental Models
- **The schema IS the API.** Tables/views/functions become REST + GraphQL endpoints automatically; design the schema as your public contract.
- **Security lives in the row, not the route.** A leaked anon key is harmless if RLS is correct, because the database itself refuses unauthorized rows.
- **`auth.uid()` is per-row by default.** Wrapping it as `(select auth.uid())` turns it into a cached initPlan run once per statement — a documented ~95% speedup on large RLS scans.

## Anti-patterns
- Exposing a table to `anon`/`authenticated` without enabling RLS (open data).
- `SECURITY DEFINER` function without `set search_path = ''` (privilege-escalation / injection).
- Calling `auth.uid() = user_id` un-wrapped in a hot policy, and forgetting an index on the policy's `user_id` column.
- Relying on `auth.uid() = user_id` for anon traffic — `auth.uid()` is NULL when unauthenticated and `NULL = x` is false-ish; guard with `IS NOT NULL` if needed.
- Using transaction-mode pooling (6543) with prepared statements / session features.
- Using `json` where you query into it (reparsed every time) instead of `jsonb`.

## Code Examples
```sql
-- Function + trigger that audits salary changes
create function update_salary_log()
returns trigger language plpgsql as $$
begin
  insert into salary_log(employee_id, old_salary, new_salary)
  values (new.id, old.salary, new.salary);
  return new;
end;
$$;

create trigger salary_update_trigger
after update on employees
for each row
execute function update_salary_log();
```
- **What it demonstrates**: canonical `returns trigger` function (access to `new`/`old`, returns `new`) bound by `CREATE TRIGGER` with `AFTER UPDATE ... FOR EACH ROW`.

```sql
-- Privileged read, callable by authenticated, safe
create or replace function current_team_data()
returns setof teams
language plpgsql
security definer set search_path = ''
as $$
begin
  return query select * from public.teams where id = (select auth.uid());
end;
$$;
revoke execute on function public.current_team_data from public, anon;
grant  execute on function public.current_team_data to authenticated;
```
- **What it demonstrates**: SECURITY DEFINER with locked search_path, fully-qualified objects, and explicit execute grants.

## Reference Tables

Index types:
| Type | Use | Syntax |
|---|---|---|
| B-tree (default) | `=`, ranges, ORDER BY, joins | `CREATE INDEX i ON t(col);` |
| GIN | jsonb `@>`, arrays, FTS tsvector | `... USING gin(col);` |
| GiST | geometric, proximity | `... USING gist(col);` |
| BRIN | huge, naturally-ordered (created_at) | `... USING brin(col);` |
| Hash | equality only (rare) | `... USING hash(col);` |
| Partial | subset of rows | `... (col) WHERE status='shipped';` |
| pgvector | ANN search | `... USING hnsw (emb vector_cosine_ops);` |

Pooler modes:
| Mode | Host : Port | Best for |
|---|---|---|
| Direct | `db.[ref].supabase.co:5432` | migrations, pg_dump, persistent |
| Supavisor session | `...pooler.supabase.com:5432` | persistent backend, IPv4 networks |
| Supavisor transaction | `...pooler.supabase.com:6543` | serverless/edge (no prepared stmts) |

Notable extensions (`CREATE EXTENSION <name> WITH SCHEMA extensions;`):
| Extension | Purpose |
|---|---|
| `vector` (pgvector) | embeddings + ANN (`<->` L2, `<#>` inner, `<=>` cosine) |
| `pg_net` | async HTTP from SQL (`net.http_post`) |
| `pg_cron` | scheduled jobs |
| `pg_stat_statements` | query performance stats |
| `index_advisor` / `hypopg` | index recommendations |
| `postgis` | geospatial |
| `pg_graphql` | GraphQL endpoint |
| `pgmq` | message queue |

## Worked Example
```sql
-- 1. Table
create table todos (
  id bigint generated always as identity primary key,
  user_id uuid not null references auth.users on delete cascade,
  task text not null,
  inserted_at timestamptz default now()
);

-- 2. Lock it down
alter table todos enable row level security;
grant select, insert, update, delete on public.todos to authenticated;

create policy "Users manage own todos"
on public.todos for all to authenticated
using ( (select auth.uid()) = user_id )
with check ( (select auth.uid()) = user_id );

-- 3. Index the RLS column (critical for scan performance)
create index todos_user_id_idx on public.todos using btree (user_id);

-- 4. Query (planner-friendly: duplicate the policy filter)
select * from public.todos where user_id = (select auth.uid());
```
Result: an auto-exposed `/todos` API where each user sees only their rows, `ON DELETE CASCADE` cleans up when a user is removed, and the policy scan is index-backed with cached `auth.uid()`.

## Key Takeaways
- Enable RLS on every exposed table; write policies per operation (`USING` for read/delete, `WITH CHECK` for insert, both for update).
- Wrap `auth.uid()` in `(select ...)` and index the columns your policies filter on.
- `SECURITY DEFINER` requires `set search_path = ''` + fully-qualified names; grant `execute` narrowly.
- Choose pooler mode by client: 6543 transaction for serverless, 5432 session/direct for long-lived and migrations.
- Use `jsonb` + GIN, generated `tsvector` + GIN for FTS, and pgvector HNSW/IVFFlat for embeddings.
- Diagnose with `EXPLAIN ANALYZE` and `pg_stat_statements`; let `index_advisor` suggest indexes.
