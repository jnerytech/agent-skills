# Appendices: When to Hire an Expert & Resources

## Core Idea
Two short appendices: signals that it's time to bring in a **documentarian** (documentation specialist), and a curated toolkit of courses, templates, style guides, and automation tools to keep working with.

## Frameworks Introduced
- **Documentarian**: a documentation specialist (a.k.a. technical writer, content-focused UX designer/PM/engineer — term from Write the Docs). Hire at documentation inflection points.
- **When-to-hire signals** (each maps to a chapter's work at scale):
  - Meeting a **new set of user needs** you don't understand (use cases, journeys, end-to-end testing) — Ch 1.
  - **Increasing support deflection** — turn one-to-one support into scalable docs — Ch 8.
  - **Managing large documentation releases** that eat engineering time — Ch 7/11.
  - **Refactoring an information architecture** for large doc sets — Ch 10.
  - **Internationalization & localization** pipelines.
  - **Versioning docs with software** (scalability + SEO).
  - **Accepting user contributions** to docs.
  - **Open-sourcing documentation** (templates, standards, review processes).

## Key Concepts
- **Diátaxis Framework** (diataxis.fr): a widely-adopted model structuring docs into four user-need quadrants — tutorials, how-to guides, reference, explanation. Complements this book's content types (Ch 2).
- **The Good Docs Project** (thegooddocsproject.dev): open-source templates, processes, and guides.
- **C4 model** (c4model.com): standardized, developer-friendly architecture diagramming at levels of abstraction (Ch 6).
- **Time to Hello World (TTHW)**: adoption-ease metric (Ch 9).

## Key Takeaways
1. Hire a documentarian at inflection points (scale, IA refactor, i18n, versioning, open-sourcing, support deflection).
2. Diátaxis and The Good Docs Project give ready-made structure and templates.
3. Standardize with a public style guide + a prose linter (Vale).
4. Automate reference generation (OpenAPI/Javadoc), link checking (htmltest), and hosting/versioning (Read the Docs).
5. Plug into the Write the Docs community for ongoing learning.
