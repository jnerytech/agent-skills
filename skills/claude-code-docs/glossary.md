# Glossary — Claude Code Docs (memory, skills, subagents, hooks)

**`@path` import** — Inlines another file into a CLAUDE.md at launch. The path is relative to the importing file, the chain goes at most 4 hops deep, and spaces are escaped with `\`. (ch02)
**`additionalContext`** — Hook output that is injected into Claude's context. When several hooks return it, their text is concatenated. (ch15)
**AGENTS.md** — The cross-tool instruction file. It is read natively only when no CLAUDE.md is on the path, under the default `claude-md-or-agents-md` setting. (ch03)
**Agent hook** — `type: "agent"`, an experimental subagent verifier with tools. It has a 60 s timeout and up to 50 tool-use turns. (ch16)
**Agent memory** — The `memory: user|project|local` field gives a subagent a persistent directory. Up to 200 lines or 25KB of its `MEMORY.md` is injected. (ch11)
**`allowed-tools`** — In a skill, tools pre-approved for the invoking turn only. It grants access and never restricts anything. (ch07)
**Auto memory** — Notes Claude writes for itself in `~/.claude/projects/<project>/memory/`. There is one per repo, shared across worktrees and local to the machine. (ch04)
**Bundled skill** — A skill that ships with Claude Code (`/doctor`, `/verify`, `/claude-api`…). Turn them off with `disableBundledSkills`. (ch05)
**`CLAUDE_ENV_FILE`** — A script preamble run before each Bash command. Hooks write `export` lines into it. (ch14)
**CLAUDE.local.md** — Personal, gitignored project instructions. In each directory it is appended after CLAUDE.md. (ch01)
**CLAUDE.md** — Instruction files loaded at session start, at org, user, project or local scope. They are context, not enforcement. (ch01)
**`claudeMdExcludes`** — Absolute-path globs that skip CLAUDE.md and rules files. Arrays merge across settings layers. (ch03)
**`context: fork`** — Runs a skill body as the prompt of a fresh subagent with no chat history. It runs in the background by default. (ch08)
**`continueOnBlock`** — A prompt-hook flag that sends the block reason back to Claude instead of ending the turn. (ch16)
**`description`** — For skills and subagents, the only text Claude matches requests against. For skills, the combined `description` + `when_to_use` is capped at 1,536 chars. (ch06, ch10)
**`disable-model-invocation`** — `true` makes a skill user-only and removes its description from context. (ch07)
**`disallowedTools`** — A subagent denylist applied before `tools`. An entry with a specifier still removes the whole tool. (ch11)
**Dynamic context injection** — The output of `` !`cmd` `` or ```` ```! ```` replaces the placeholder before Claude reads the skill. (ch08)
**Exit code 2** — The blocking hook exit. The reason goes on stderr. Exit 0 means "no objection", not approval. (ch15)
**Explore / Plan** — Read-only built-in subagents. They skip CLAUDE.md and cannot be resumed. (ch10)
**Fork** — A subagent that inherits the conversation, system prompt, tools, model and prompt cache. Started with `/subtask`. (ch13)
**general-purpose** — The built-in subagent with all tools. It is the fallback when no `subagent_type` is given. (ch10)
**HTTP hook** — `type: "http"`. It POSTs the hook JSON to a URL and reads the decision from the response body. (ch16)
**`hookSpecificOutput`** — The JSON wrapper for event-specific hook output. Fields outside it are silently ignored. (ch15)
**`if` field** — A per-handler filter in permission-rule syntax. It applies only to tool events and is best-effort, failing open. (ch15)
**Managed policy CLAUDE.md** — The org file (`/etc/claude-code/CLAUDE.md` on Linux/WSL) or managed `claudeMd`. It loads first and cannot be excluded. (ch01, ch03)
**Matcher** — The group-level hook filter. What it tests depends on the event: tool name, session source, notification type, and so on. (ch15)
**`MEMORY.md`** — The auto memory index. Only the first 200 lines or 25KB load. (ch04)
**`omitClaudeMd`** — Starts a subagent without user, project or local CLAUDE.md. Managed files still load. (ch10)
**`paths`** — Glob frontmatter that scopes a `.claude/rules/` file or a skill to matching files. (ch02, ch06)
**`permissionDecision`** — `PreToolUse` hook output: `allow`, `deny`, `ask` or `defer`. (ch15)
**Prompt hook** — `type: "prompt"`, a single LLM call that returns `{ok, reason}`, with a 30 s timeout. (ch16)
**Scope precedence (subagents)** — Managed > `--agents` > `.claude/agents/` > `~/.claude/agents/` > plugin. (ch10)
**`SendMessage`** — Resumes a finished subagent by ID or name, with its full history. (ch12)
**Skill** — A directory with a `SKILL.md`. Invoked as `/name` or auto-loaded when its `description` matches. (ch05)
**Skill content lifecycle** — A rendered skill body stays in the conversation and is never re-read. After compaction it keeps its first 5,000 tokens, within 25,000 total. (ch07)
**Skill listing budget** — 1% of the context window (`skillListingBudgetFraction`). Descriptions are dropped least-invoked first. (ch09)
**`skillOverrides`** — Per-skill visibility: `on`, `name-only`, `user-invocable-only` or `off`. (ch08)
**`stop_hook_active`** — Input flag that is true when Claude is already continuing because a Stop hook blocked. Use it as the loop guard. (ch16)
**Subagent** — A Markdown + YAML worker with its own context window, prompt, tools and permissions. It returns a summary. (ch10)
**`updatedInput`** — A `PreToolUse` rewrite of tool arguments. When several hooks return it, the last one to finish wins. (ch15)
**`user-invocable`** — `false` hides a skill from the `/` menu, but Claude can still invoke it. (ch07)
**`${CLAUDE_SKILL_DIR}`** — The skill's own directory. It expands in the body and in `allowed-tools`. (ch06)
