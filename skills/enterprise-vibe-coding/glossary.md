# Glossary — Enterprise Vibe Coding for Agentic Engineering

**A2A (Agent-to-Agent protocol)** — Google's 2025 standard for agents delegating to and collaborating with other agents across products (Ch 2)
**Advice / Action / Transaction boundary** — three tiers of what a customer-facing agent may do: recommend freely, make low-risk reversible changes in scope, never touch checkout/payment (Ch 6)
**Agent (primitive)** — named collaborator with one job, an explicit tool allowlist and escalation rules; "a prompt is the recipe, the agent is the cook" (Ch 3)
**Agent identity** — distinct principal per agent (Entra Agent ID, IAM role, OAuth) acting on behalf of the originating user (Ch 5)
**Agent-native tool** — tool where work starts from an issue/PR, the agent plans before acting, and runs in an isolated branch (Ch 8)
**Agentic AI** — multiple agents, tools, data and human overseers organized to pursue goals no single agent could (Ch 2)
**Agentic audit trail** — unified record of every prompt, tool call, policy decision, approval and output; "the deterministic shadow of a probabilistic system" (Ch 5)
**Agentic DevOps** — DevOps extended with bounded reasoning systems in the pipeline; five patterns from intent-driven execution to collaborative systems (Ch 4)
**Agentic workflow** — version-controlled definition pinning trigger, permissions, allowed tools/MCP, steps and human gates (`.github/workflows/*.md` → `.lock.yml`) (Ch 4, Ch 5)
**AI agent** — an LLM plus perception, reasoning/planning, tool use and memory, running in an agent loop (Ch 2)
**Autonomy gradient** — autonomy as low (human accepts each step), bounded (approval at thresholds), or standing authority (audited); "a gradient, not a switch" (Ch 2)
**Autopilot** — mode where the agent keeps going between reasoning steps; a separate dial from permissions (Ch 7)
**AX (Agent Experience)** — Biilmann's sense: the agent's experience using a platform; this book's sense: the human's experience of working with persistent agents, i.e. understandable, steerable, auditable, accountable (Ch 8)
**Blast radius** — potential damage of an action; sets how deterministic its control must be (Ch 5)
**Decision boundaries** — Level 0 forbidden, 1 human approval, 2 logged and reviewable, 3 fully autonomous; each action maps to exactly one (Ch 5)
**Delivery loop** — recurring, verifiable workflow driving an agent from trigger to governed outcome (Ch 7)
**Done-condition** — verifier gate that fails while any acceptance checkbox is unchecked (Ch 7)
**Engine prompt** — the prompt a scheduler fires each tick to reconstruct state and advance one capability (Ch 7)
**Executable contract** — issue with goals, constraints and machine-checkable acceptance criteria (Ch 7)
**Failure path** — designed recovery: idempotency, bounded retries, compensation, human escalation with full trace (Ch 6)
**Field test (three questions)** — who decided? what were the constraints? what evidence proves it works? A missing answer means it was vibed (Ch 1)
**File-mediated coordination** — agents hand off via repo artifacts, not model context (Ch 5)
**Frontier firm** — organization where human-agent teams are the everyday unit of work (Ch 1, Ch 2)
**Gate 1 / Gate 2** — the human approvals of the plan and of the final merge in a delivery loop (Ch 7)
**Governance engineering** — moving consequential behavior toward the deterministic end of the spectrum (Ch 5)
**Governed artifacts** — specs, ADRs, diagrams and NFRs committed to the repo, so downstream agents read context instead of having it restated (Ch 4)
**Handoff (pattern)** — MAF orchestration where control passes by live context and only one agent speaks at a time (Ch 6)
**Harness Engineering** — engineering the agent's execution environment: tools, sandboxes, permissions, verification, observability (Ch 7)
**Hook** — deterministic script fired on a lifecycle event; the only mechanism between model decision and action (Ch 3, Ch 5)
**HVE (Hypervelocity Engineering)** — Microsoft's AI-native delivery model: small multidisciplinary teams + solution accelerators + AI across the lifecycle, scaling through primitives instead of headcount (Ch 1)
**HVE maturity spectrum** — 1 Traditional, 2 AI-assisted, 3 Vibe coding, 4 Structured agentic, 5 HVE; assessed on seven dimensions (Ch 1)
**Instruction hierarchy** — Tier 1 global, Tier 2 scoped (`applyTo` / nested `CLAUDE.md`), Tier 3 memory files; short, imperative, scoped (Ch 5)
**Instructions (primitive)** — always-on rulebook auto-loaded in every interaction (Ch 3)
**Loop Engineering** — "design the loop, not the prompt" (Osmani): optimizing the system that repeatedly orchestrates work (Ch 7)
**Macro orchestrator** — runtime (Copilot Agent Mode, Claude Code) composing primitives around each request (Ch 3)
**MAF orchestration patterns** — Sequential, Concurrent, Group chat, Magentic, Handoff (Ch 6)
**MCP (Model Context Protocol)** — open standard connecting agents to tools/data through one interface; govern each server like a production dependency (Ch 2, Ch 3)
**Policy-as-code** — machine-evaluable org rules (OPA/Rego, Cedar), declarative, testable, auditable and versioned, outside any prompt or model (Ch 5)
**Primitive** — small, versioned, composable file encoding agent behavior; concept surface-agnostic, files surface-specific (Ch 3)
**Prompt (primitive)** — reusable task template with a fixed output outline; Claude Code slash command (Ch 3)
**Return Questions (five)** — goal? what changed? why? what evidence? what decision is needed from me now? (Ch 8)
**RPI cadence** — Research → Plan → (human approval) → Implement, in small evidenced PRs (Ch 4)
**Single agentic surface** — one intent layer over many agents, with apps moving "one layer down" (Ch 2)
**Skill (primitive)** — packaged procedure (`SKILL.md` + scripts) for how to do a complex task; include failure modes (Ch 3)
**Steered agentic development** — humans set boundaries, decide and stay accountable; agents execute and produce evidence (Ch 1)
**Stochastic-to-deterministic spectrum** — five bands, from free generation to fully deterministic gates (Ch 5)
**Tick** — one scheduled firing of a loop; advances exactly one capability, then stops (Ch 7)
**Vibe coding** — Karpathy (2025): "forget that the code even exists"; fine for prototypes, fails at enterprise scale (Ch 1)
**Vibe-coding flywheel** — velocity spike → consistency erosion → review fatigue → incident acceleration → velocity collapse (Ch 1)
**Vibe working** — Microsoft 2025: state intent, let agents handle the moving parts, show up for judgment (Ch 2)
