# Glossary

**Agent** — LLM system looping observe→decide→act, choosing tools; vs. **engine** (runs once, stops) and **chatbot** (stateful dialogue only) (Ch 1, 5, 11)
**Agentic workflow** — fixed sequence where the LLM only picks among predefined options, unlike a full agent (Ch 5)
**Benchmarks (IFEval, BBH, MATH, GPQA, MuSR, MMLU-Pro, HumanEval)** — standardized tests for instruction-following, reasoning, math, science, and code correctness (App C)
**Chain of Thought (CoT) / Tree of Thought (ToT) / Thread of Thought (ThoT)** — examples with explicit reasoning steps; exploring multiple reasoning paths; staying focused amid noisy context (Ch 2)
**Checkpoint / Checkpointer / Thread** — a graph-state snapshot per super-step, saved by a pluggable saver keyed by `thread_id` (Ch 14)
**Chunk / chunking strategies / TokenTextSplitter** — a text fragment sized for embedding/context limits; hierarchy splitters preserve structure, fixed-size/token splitters risk mid-sentence cuts (Ch 3, 6, 8)
**Content-store query generation (text-to-SQL, semantic SQL, KG-RAG)** — LLM generates SQL, vector-ranked SQL, or Cypher/SPARQL for relational/graph databases (Ch 10)
**Context window** — max tokens an LLM accepts in one prompt; varies hugely by model (Ch 3, App C)
**Document / DocumentLoader** — LangChain's container for text plus metadata; loaders (Wikipedia, PDF, `DirectoryLoader`) produce Document lists (Ch 1, 3, 7)
**Embedding** — a vector representation of text capturing meaning, used for similarity/semantic search (Ch 1, 6)
**Grounding / Hallucination** — grounding prompts with trusted context for verified answers; hallucination is a fabricated response from poor data/context (Ch 1, 6)
**Guardrail / pre-/post-model hook** — a rule-, retrieval-, or model-based check keeping an agent in scope; hooks rewrite input/output around the LLM call (Ch 14)
**Human-in-the-loop** — a pause point where a human approves a critical agent action before it finalizes (Ch 1, 14)
**Hypothetical Document Embeddings (HyDE)** — the LLM's fabricated answer, not the question, drives retrieval; also used per-chunk at indexing time (Ch 8, 9)
**In-context learning (zero/one/few-shot)** — teaching an LLM a task via 0-N prompt examples instead of fine-tuning (Ch 2)
**LangSmith tracing** — records inputs/outputs per chain/agent step in a "project" for debugging (Ch 7, 11, 12)
**LCEL / Runnable / StrOutputParser** — `|` syntax composing `Runnable`s into pipelines; `RunnableLambda`/`Parallel`/`Passthrough` wrap a function, run branches concurrently, or forward input unchanged; `StrOutputParser` extracts plain text (Ch 1-4, 7, App A)
**Local inference engines (llama.cpp, Ollama, vLLM, llamafile, LM Studio, LocalAI, GPT4All)** — run quantized LLMs locally, mostly via an OpenAI-compatible API (App E)
**MapReduce summarization / Refine** — MapReduce splits→maps chunks in parallel→reduces to one summary; Refine folds docs in sequentially (Ch 3)
**Memory (short-term, long-term user/app)** — context per session, per-user across sessions, or shared across all users (Ch 14)
**MCP host/client/server** — host's client connects to servers exposing tools; validated via MCP Inspector, built with FastMCP, aggregated via `MultiServerMCPClient` (Ch 1, 13)
**Mixture-of-Experts (MoE)** — activates only a parameter subset per token, cutting inference cost (App C)
**Multi-query retrieval / query decomposition** — splitting a compound question into independent/interdependent sub-questions, retrieved and merged (Ch 4, 9)
**MultiVectorRetriever / ParentDocumentRetriever** — links a small retrieval embedding (child chunk/summary/question) to a larger synthesis chunk via a docstore (Ch 8)
**OpenAI Completions API / ChatOpenAI** — raw OpenAI messages API, and LangChain's wrapper unifying chat calls behind `.invoke()` (Ch 2, App A)
**Prompt structure / XML-style tags** — sections (Persona, Context, Instruction, Input, Steps, Tone, Output, Examples), optionally wrapped in tags like `<Persona>` (Ch 2)
**PromptTemplate / FewShotPromptTemplate** — a parametrized prompt with `{variable}` placeholders; the few-shot variant pairs examples with a template and suffix (Ch 2, App A)
**Quantization (GGUF/GGML)** — reducing weight precision (16-bit→4-bit) to shrink size and speed inference (App E)
**Query rewriting / Rewrite-Retrieve-Read / Step-back prompting** — an LLM rewrites or broadens a question for retrieval, keeping the original for synthesis (Ch 4, 9)
**Query router** — an LLM classifier (structured output) mapping a question to the right retriever/data source (Ch 10, 12)
**ReAct pattern / tool-calling protocol** — interleaves LLM reasoning with tool actions until a final answer, via `tool_calls` against tool schemas (Ch 11)
**Reciprocal Rank Fusion (RRF) / retrieval postprocessing** — merges ranked lists via `1/(rank+k)`; also filters by threshold, keywords, or recency before synthesis (Ch 9, 10)
**RemainingSteps / ToolNode / tools_condition** — LangGraph built-ins bounding tool rounds, executing tool calls, and routing when present (Ch 11)
**Retriever / vector store vs. library** — embeds a query to fetch similar chunks; a store (Chroma) holds text/metadata with CRUD, a library (FAISS) is in-memory and immutable (Ch 1, 6, 7)
**Router agent / Supervisor agent** — router classifies and delegates a query once; supervisor wraps agents as tools, invoking them repeatedly (Ch 12)
**Self-querying** — turns a question into a metadata filter plus semantic-search component (Ch 10)
**State rewinding / time travel** — replaying a persisted graph to a checkpoint via `get_state_history()` and resuming (Ch 14)
**StateGraph** — directed graph of typed state, nodes (partial updates), and edges incl. conditional edges and `END` (Ch 5)
**Tool / Toolkit** — an external function an LLM invokes via the tool-calling protocol; a toolkit is an agent's full tool set (Ch 1, 11)
