# Glossary — Apache Kafka in Action

**acks** — Producer setting for when the leader confirms a write: `0` never, `1` leader only, `all`/`-1` all ISRs; default `all` since 3.0 (Ch 5)
**Active / standby controller** — The quorum-elected KRaft controller that assigns partitions and leaders; standbys take over instantly (Ch 7)
**Alert fatigue** — Ignoring alerts after repeated false positives, so real incidents slip through (Ch 15)
**Backpressure** — Broker slowing producers down for slow consumers; re-couples them (classic MQ, not Kafka) (Ch 17)
**Backward / forward / full compatibility** — New consumer reads old data (update consumers first) / old consumer reads new data (update producers first) / both; *transitive* = across all versions (Ch 13)
**broker.rack / client.rack** — Location labels for rack-aware replica placement and fetch-from-closest-replica (KIP-392) (Ch 9, 16)
**Change data capture (CDC)** — Streaming DB changes from the transaction log (Debezium) instead of polling tables (Ch 11, 18)
**Co-partitioning** — Same key and same partition count on both join inputs; required for streaming joins (Ch 12)
**Consumer group** — Consumers sharing a `group.id`; at most one consumer per partition; separate groups read independently (Ch 4, 9)
**Consumer lag / records-lead** — LEO − committed offset / distance from the oldest retained record; low lead + high lag = data-loss risk (Ch 9, 15)
**`__cluster_metadata`** — Internal KRaft topic holding all cluster metadata (Ch 7)
**`__consumer_offsets`** — Internal compacted topic (50 partitions) storing committed group offsets (Ch 3, 9)
**Cruise Control** — LinkedIn tool: analyzer + goals → proposal → executor rebalances partitions/leaders (Ch 14)
**Data on the inside / outside** — Service-private mutable data (DB) vs. immutable exchanged data (Kafka) — Helland (Ch 17)
**Data mesh / data product** — Domain-owned, schema-governed data published on a self-service platform (Ch 18)
**Dirty ratio** — Uncompacted ÷ total log; compaction eligible at `min.cleanable.dirty.ratio` (0.5) (Ch 10)
**ELR (eligible leader replicas)** — Replicas caught up to the HWM that can become leader when ISR < `min.insync.replicas` (Ch 3, 8)
**Grace period** — How long a window accepts late records; without one they are dropped (Ch 12)
**Group coordinator / group leader** — Broker managing membership and heartbeats / first consumer, which computes the assignment (Ch 9)
**High Watermark (HWM)** — Smallest LEO across ISRs; the commit boundary and the limit of what consumers can read (Ch 8)
**Idempotent producer** — `enable.idempotence=true`; producer ID + sequence numbers drop duplicates and enforce order per partition (Ch 5)
**ISR (in-sync replicas)** — Replicas that fetched the leader's data within `replica.lag.time.max.ms` (30 s) (Ch 3, 5, 8)
**KRaft** — Kafka's built-in Raft consensus; production-ready 3.3, ZooKeeper removed in 4.0 (Ch 7)
**KStream / KTable** — Unbounded event stream / latest value per key, backed by a state store + changelog topic (Ch 12)
**Leader epoch** — Counter bumped on every leader change; fences stale replication (Ch 8)
**Log compaction** — Keeps only the latest record per key; needs keys; never touches the active segment (Ch 10)
**Log End Offset (LEO)** — Offset after the last record a replica holds (Ch 8)
**Log retention** — Deletes whole segments once their newest record exceeds `retention.ms` (7 d) or size exceeds `retention.bytes` (Ch 10)
**Log segment** — `.log` + `.index` + `.timeindex` files named by base offset; rolls at 1 GiB or 7 days (Ch 8)
**MirrorMaker 2** — Connect-based async cluster replication with remote topics prefixed by source cluster (Ch 16)
**min.insync.replicas** — Minimum ISR count to accept `acks=all` writes; below it → `NotEnoughReplicasException` (Ch 5)
**Offset** — Per-partition sequential position: the record's address and the consumer's bookmark (Ch 4)
**Outbox table** — Denormalized, consumer-ready table written in the same DB transaction, then published via CDC (Ch 18)
**Partition** — Ordered log inside a topic; unit of parallelism, ordering, and replication (Ch 1, 4)
**Purgatory** — Broker area where requests wait for follower acks or fetch thresholds (Ch 8, 15)
**Rebalance** — Redistribution of partitions in a group (JoinGroup/SyncGroup/Heartbeat); classic protocol stops the world (Ch 9)
**Repartition topic** — Internal `-repartition` topic created when a key changes before a stateful op (Ch 12)
**Schema registry** — Stores/versions/checks schemas; messages carry only a schema ID; validation is client-side (Ch 13)
**Share groups** — Upcoming "queues for Kafka": more consumers than partitions, no strict order (Ch 6)
**Single Message Transformation (SMT)** — Per-record transform in Kafka Connect; not for ETL (Ch 11)
**Static membership** — `group.instance.id` + long `session.timeout.ms`: restarts rejoin without a rebalance (Ch 9)
**Stretched cluster** — One cluster spanning ≥3 nearby DCs (≤30 ms) (Ch 16)
**Tiered storage** — Offloads old segments to object storage (3.9+) (Ch 14, 18)
**Tombstone** — Keyed record with `null` value; deletes the key on compaction, kept `delete.retention.ms` (1 d) (Ch 10)
**Transaction coordinator** — Broker running Kafka's two-phase-commit variant, writing commit/abort markers (Ch 5)
**transactional.id** — Stable ID of a transactional producer; a newer instance fences zombies (Ch 5)
**Unclean leader election** — Electing an out-of-sync replica when no ISR is left; availability over data (Ch 5)
**Worker / task (Connect)** — Connect process (same `group.id` = one Connect cluster) / unit of parallel connector work, capped by `tasks.max` (Ch 11)
**Zero-copy** — Kernel moves bytes page cache → socket without copying; disabled by TLS (Ch 6)
