# Glossary — Beyond Vibe Coding

**70% problem** — AI quickly gets ~70% of a solution (boilerplate, patterned code); the last 30% (edge cases, architecture, maintainability, production readiness) needs human expertise (Ch 1, 3, 4)
**Accidental vs. essential complexity** — Brooks's split: AI absorbs the mechanical difficulty; the problem's intrinsic difficulty stays human (Ch 3)
**Agent inbox** — single dashboard of agent tasks, progress, and items needing human attention (Ch 11)
**AI-assisted engineering** — disciplined use of AI in every SDLC phase under clear constraints, human in the driver's seat; opposite end of the spectrum from vibe coding (Ch 1)
**Architect and editor in chief** — the senior role: specify the work, then review the output for correctness (Ch 4)
**Assumption mismatch** — separately generated components disagree on a convention (e.g., date format) (Ch 8)
**Async coordination paradox** — more parallel agents make integrating their work harder (Ch 10)
**Background coding agent** — AI that takes a high-level goal, works in a sandbox, and returns a PR (Ch 10)
**Big ball of mud** — structureless code; frictionless AI feature-adding accelerates it (Ch 8)
**Bootstrappers vs. iterators** — zero-to-MVP users of AI vs. daily users for completion, refactoring, tests (Ch 3)
**Chain-of-thought** — prompting the model to reason step by step before answering (Ch 2)
**CHOP (chat-oriented programming)** — Yegge: coding via iterative prompt refinement with AI as collaborator (Ch 4)
**Coherent incorrectness** — internally consistent code misaligned with real needs because an early misunderstanding compounded (Ch 10)
**Contextual prompting** — supplying definitions, API snippets, constraints, and term clarifications (Ch 2)
**Demo-quality trap** — happy path impresses; real users hit errors, edge cases, accessibility gaps, slowness (Ch 3)
**Derivative work risk** — AI output built from someone's copyrighted input may inherit its license (Ch 9)
**Environmental drift** — small sandbox differences between agents surfacing as integration bugs (Ch 10)
**Ephemeral sandbox** — isolated VM/container with repo and deps where a background agent runs (Ch 10)
**Few-shot prompting** — giving 2–5 input→output examples before the real input (Ch 2)
**Fidelity vs. control** — prototyping-tool trade-off: match to your intent vs. ability to steer and modify (Ch 6)
**Frontend/backend contract** — agreed request/response shapes; most common site of AI mismatches (Ch 7)
**Generator vs. reviewer asymmetry** — generating code is hard, reviewing it easier; agents generate, humans specify and review (Ch 10)
**Hardening sprint** — scheduled cleanup/refactor/doc sprint after a generation burst (Ch 8)
**House of cards code** — looks complete, collapses under real-world pressure (Ch 1, 3)
**Human authorship requirement** — the US Copyright Office protects only human creative contributions, not purely AI output (Ch 9)
**Intelligent checkpointing** — an agent detects its own uncertainty and asks instead of bluffing (Ch 11)
**Intent vs. interpretation** — the gap between what you meant and what the AI chose where the prompt was ambiguous (Ch 5)
**Knowledge paradox** — seniors use AI to accelerate what they know; juniors use it to learn what to do; results differ dramatically (Preface, Ch 1, 3)
**Layering** — natural language for orchestration, formal code for precision (Ch 11)
**Majority solution effect** — AI emits the most common/simplest solution from training data; "most common doesn't mean most appropriate" (Ch 5)
**Metaprompting** — instructions about the output itself: format, order, exclusions, invalid-input behavior (Ch 2)
**Model card** — "nutrition label" of a model: uses, limits, fairness benchmarks, risks (Ch 9)
**Package hallucination** — AI invents a package name that attackers can squat with malware (Ch 8)
**Plan-first development** — spec → targeted prompts → review → integrate; AI creativity bounded by the spec (Ch 1)
**Programming with intent** — state *what*, not *how*; "the prompt becomes your new unit of thought" (Ch 1, 6, 7)
**Property-based testing** — define invariants and let a tool generate inputs/counterexamples (Ch 8)
**Proxy variable** — neutral-looking input correlated with a protected trait (zip code → race) (Ch 9)
**ReAct** — interleaving reasoning with tool/execution actions, feeding results back (Ch 2)
**Role prompting** — giving the model a persona to steer focus, tone, depth (Ch 2)
**Self-consistency** — sample several answers, trust the consensus (Ch 2)
**Shadow testing** — run the new version in parallel on real inputs, show only the live output, compare (Ch 8)
**Skill atrophy** — loss of fundamentals from over-delegation; countered by AI-free days (Ch 3, 4)
**Sunk-cost dilemma** — whether to finish the last 10–20% of a nearly right agent PR on a low-value task (Ch 10)
**Sunny-day scenario** — happy path a prototype covers while ignoring failures (Ch 6)
**Training cutoff gap** — model unaware of post-training vulnerabilities and practices (Ch 8)
**Two steps back** — each AI fix breaks something else; whack-a-mole loop (Ch 3)
**User enumeration** — specific login errors reveal which usernames exist (Ch 8)
**Vibe coding** — Karpathy's "fully give in to the vibes": prompt, accept everything, paste errors back (Ch 1)
