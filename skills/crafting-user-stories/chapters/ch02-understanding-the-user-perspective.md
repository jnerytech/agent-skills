# Chapter 2: Understanding the User Perspective

## Core Idea
Good stories start with real knowledge of the user — gathered through user research and distilled into personas, empathy maps, and journey maps that ground the team in user-centered design (UCD).

## Frameworks Introduced
- **Personas** — fictional, research-based characters representing a user segment's shared goals, needs, pain points.
  - When to use: before/while writing stories, to fill the "As a [persona]" slot with a real understanding.
  - How (4 steps): 1) conduct research (interviews, surveys); 2) identify common characteristics (demographic + psychographic + job role); 3) write a 1-page profile (name, photo, goals, challenges, behavior); 4) test and refine. Persona = **aggregate** data, not one individual.
- **Empathy Map** — visual of a user across four quadrants: **Says, Thinks, Feels, Does**.
  - When to use: to surface emotions/motivations behind behavior and find pain points.
  - How: pick the persona → collect data → fill the four quadrants collaboratively → analyze for patterns/opportunities.
- **User Journey Map (CUJ)** — visual of the steps a user takes to reach a goal across touchpoints, with their emotions at each step.
  - When to use: to find friction across a multi-touchpoint experience and spot improvement opportunities.
  - How: define the journey → identify touchpoints → identify emotions → map visually → analyze (include forward-looking "where we want the user to go").
- **Design Sprint** (Google Ventures, 5-day) — phases: **Understand → Define → Sketch → Decide → Prototype**. Time-boxed, cross-functional, ends in a tested low-fi prototype.

## Key Concepts
- **User research**: collecting data on users' needs, behaviors, preferences to drive design.
- **UCD (User-Centered Design)**: framework that involves users at every stage to build functional, usable, enjoyable products.
- **Design thinking**: empathize → ideate → prototype → test, user at the center.
- **Touchpoint**: any point where the user interacts with the org (web, call, email, social, in-person).
- **Unconscious bias**: automatic stereotyped beliefs that skew design toward the designer's own context.
- **Usability testing**: observing real users interacting to find friction.

## Mental Models
- Design for **user goals, not features** (UCD Principle 2) — evaluate every decision by how well it supports the user's task.
- Research types pair by purpose: **qualitative** (why/how — interviews, focus groups) vs **quantitative** (how many/how often — surveys, analytics).
- UCD's 7 principles: user involvement, goal/task focus, usability, accessibility (WCAG), consistency, context, iteration+feedback.

## Anti-patterns
- **Designing from your own assumptions/bias** (e.g. right-handed-only app): mitigate with diverse research participants, awareness, testing with diverse users.
- **Treating user feedback as ground truth**: users can't always articulate needs and show social-desirability bias — triangulate with usage data.
- **Using stereotypes in personas**: harmful and exclusionary; design inclusively instead.

## Worked Example
Persona profile (1-page format the author uses):

> **Name**: Sarah Smith · **Age**: 27 · **Occupation**: Marketing manager · **Location**: Urban
> **Goals**: use marketing skills in a collaborative role; manage work-life balance; travel to 2 new countries/year.
> **Challenges**: overwhelmed by workload; hard to make friends in a new city; limited travel budget.
> **Behavior**: researches jobs & networks on LinkedIn; yoga after work; explores new restaurants.

Empathy map for "John" (four quadrants):
- **Says**: "I wish this had more features"; "I hate the load time."
- **Thinks**: "I need a product that keeps up with my pace"; "not sure I trust this company."
- **Feels**: frustrated by bugs/slowness; disappointed when expectations aren't met.
- **Does**: visits site often; seeks workarounds; leaves negative reviews on social media.

→ Insights drive concrete action: add features, optimize load speed, revisit pricing.

## Key Takeaways
1. Fill the persona slot in a story with research, not guesses.
2. Personas are aggregate, one-page, photo+name+goals+challenges+behavior.
3. Empathy maps (Says/Thinks/Feels/Does) expose the *why* behind behavior.
4. Journey maps reveal cross-touchpoint pain points and forward-looking opportunities.
5. Pick research type by question: qualitative for depth, quantitative for scale.
6. Guard against unconscious bias by testing with diverse users.
