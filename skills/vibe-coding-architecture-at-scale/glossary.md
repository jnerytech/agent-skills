# Glossary — Vibe Coding Architecture at Scale

**Adherence rate** — share of N headless trials whose output passes a rule's deterministic detector (Ch 3f)
**Agent memory** — durable cross-session facts the agent writes for itself with no human review gate; a lead, not a citation (Ch 3e)
**Aggressive Discarding** — on red builds or sprawling diffs, `git reset --hard` immediately instead of coaching the AI out (Ch 24)
**@AIContract** — VibeTags annotation freezing a method's public signature while the body may change (Ch 4)
**@AILocked** — VibeTags "do not touch" marker; enforced only by a CI gate or hook, never by generated Markdown alone (Ch 4, 4b, 21)
**Attacker Agent** — adversarial agent that sees only the contract and a running endpoint and is paid to break it (Ch 20)
**Autonomy budget** — authority and infrastructure a team needs to ship without synchronous handoffs (Ch 11d)
**Beautifully Deceptive Code** — AI output that looks most confident precisely when it is wrong (Ch 2)
**Binding power** — adherence with a rule minus adherence with it deleted; does the sentence do any work? (Ch 3f)
**Characterization test** — records what legacy code does today, bugs included (Ch 8c)
**Configuration Surface** — the harness slots (instructions, skills, subagents, hooks) where intent stops being re-typed (Ch 3d)
**Connascence** — two components are connascent if changing one forces a coordinated change in the other (Ch 1, 2b)
**Context Diet** — standing instructions kept short, scoped and non-contradictory (Ch 3)
**Context firewall** — a fresh subagent per task so detail never accumulates in the coordinator (Ch 12)
**Context Locality** — share of a change's required knowledge inside one module boundary (Ch 3c)
**Context rot / fatigue** — output quality decaying as the window fills with undifferentiated guidance (Ch 3, 11)
**Decision density** — share of a task that is "decide" versus "execute"; picks the model tier (Ch 23b)
**Demo-scale lie** — tiny fixtures hide O(n²) behind O(n log n) (Ch 17b)
**Dependency tyranny** — the generator's preference for installing a library over writing 30 lines (Ch 18b)
**Drained evidence** — a detector reading a counter after the state it measured reset (Ch 20b, 20d)
**Dumb pipe, smart sandbox** — CI runs fixed commands with no agent and no standing credentials; intelligence lives in sandboxes (Ch 21)
**EARS** — "WHEN [trigger], THE SYSTEM SHALL [response]" requirements grammar (Ch 7, 9)
**Enforcement Gap** — generation velocity (thousands of lines/hour) vs fixed human review velocity (Ch 1b)
**Enforcer set** — files that do the testing (arch tests, contracts, CI workflows) kept outside every agent's writable scope (Ch 21)
**Entity trap** — Manager/Service God object wrapped around one entity; the generator's favorite shape (Ch 2b)
**Escaped-defect rate** — defects reaching production; the quality number that matters (Ch 11e)
**Expand / Migrate / Contract** — additive change ships with features; destructive removal is a later, separate, justified migration (Ch 18, 18c)
**Fitness function** — mechanism giving an objective, automatic verdict on one architecture characteristic (Ch 2b, 5)
**Forced collision** — parking threads at a barrier and releasing them together to reproduce a race (Ch 17)
**Green for the wrong reason** — a test that always passed for a reason unrelated to its name (Ch 20b)
**Gripe** — structured Inquisitor finding: Target, Violation + rule cited, Evidence file:line, Remediation (Ch 22)
**Guide Right** — steering generation by specifying the box and invariants, not syntax (Ch 2)
**Healthy band** — asserted range an aggregate simulation metric must stay inside (Ch 20c)
**Hook** — deterministic code fired on loop events; the only slot that enforces instead of advising (Ch 3d)
**Inquisitor** — adversarial CI reviewer with an opposing objective; sees diff + committed rules; may block, never approve (Ch 22)
**Jevons Effect** — cheaper code raises demand to a new equilibrium; the backlog never drains (Ch 1b)
**Lead not a citation** — recalled memory must be verified against current code before asserting (Ch 3e)
**Load-bearing bug** — defect whose persisted output others now depend on (Ch 18c)
**Load-bearing intent** — prompts/specs/rules whose silent change would break something; versioned in `prompts/` (Ch 23)
**Masked exit code** — `run_suite | tail` reports tail's status, turning red green (Ch 20b, 21b)
**Paradox of Local Velocity** — speeding one step without touching the constraint only piles WIP (Ch 11d)
**PCE (Process Cycle Efficiency)** — Touch Time ÷ Lead Time; AI coding can drop it to ~2.4% (Ch 11d)
**Prefix determinism** — static context first, dynamic last, so the prompt cache stays valid (Ch 3, 3c)
**Prompt lineage** — diffing versioned intent alongside code to find where an instruction drifted (Ch 23)
**Ratchet pattern** — baseline existing violations, fail only on new ones, delete allowances as code is touched (Ch 5, 8c)
**Regeneration gap** — generated guardrail files silently diverge from their annotations (Ch 4b)
**Save state** — commit of a guardrail-certified known-good state used as a reload point (Ch 24)
**Shift Left** — the architectural decision exists in enforceable form before the prompt that could violate it (Ch 2)
**Slopsquatting** — registering package names models repeatedly hallucinate (Ch 18b)
**Staleness Principle** — unverified documentation is a liability with a shelf life (Ch 3b)
**Tier 1 / 2 / 3** — root invariants (10–20 lines) / directory-scoped rules / per-element annotations (Ch 3)
**Tipping Point** — between the 10th and 50th file, vibe coding starts producing spaghetti (Ch 1)
**Two-AI Gripe** — Generator vs Inquisitor: the system reviews itself (Ch 22)
**Untrusted input** — every byte the agent didn't author and you didn't write (Ch 19)
**Vibe Architecture** — human intent in, automated machine enforcement out, zero tax on the flow (Ch 1)
**VibeTags** — the author's compile-time `@AI…` annotation processor that generates per-tool AI config (Ch 4)
**Work order** — self-contained brief a strong model writes and a cheap model executes (Ch 23b)
**Zero Inter-Prompt Drift** — never start a new prompt until the last success is committed (Ch 24)
