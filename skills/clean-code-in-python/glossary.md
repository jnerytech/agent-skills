# Glossary — Clean Code in Python (2nd ed.)

**Abstract base class (ABC, PEP-3119)** — `abc` construct defining an interface; `@abstractmethod` forces subclasses to implement it (Ch 4)
**Adapter** — wrapper that makes an incompatible interface (often third-party) conform to the one your code expects; prefer composition (Ch 9, Ch 10)
**Assignment expression (`:=`, PEP-572)** — binds a name inside an expression to avoid repeating a call (Ch 2)
**Asynchronous generator (PEP-525)** — `async def` with `yield`; consumed with `async for` (Ch 7)
**Baseline** — the full pinned list of delivered packages and versions, so builds are repeatable (Ch 10)
**black** — deterministic, all-or-nothing formatter applying a strict PEP-8 subset; `--check` for CI (Ch 1)
**Borg pattern** — monostate where all instances share one `__dict__` (Ch 9)
**Chain of responsibility** — handlers linked by `successor`; each handles or forwards the request (Ch 9)
**Class decorator (PEP-3129)** — callable that takes a class and returns a modified class (Ch 5)
**Cohesion** — how strongly an object's parts serve one well-defined purpose; aim high (Ch 3)
**Command and query separation** — a method either does something or answers something, never both (Ch 2)
**Composite** — tree of leaves and containers treated uniformly by clients (Ch 9)
**Conceptual integrity** — one shared library is the single reference for how a thing is done (Ch 10)
**Container iterable** — object whose `__iter__` returns a fresh generator each call, so it can be iterated repeatedly (Ch 2, Ch 7)
**Context manager** — object implementing `__enter__`/`__exit__` (or `@contextmanager`) to wrap pre/post logic (Ch 2)
**Coroutine** — function that can suspend/resume: generator-based (`send`/`throw`/`close`) or `async def` (Ch 2, Ch 7)
**Coupling** — degree of dependency between objects; aim low (Ch 3)
**Data descriptor** — descriptor implementing `__set__`/`__delete__`; takes precedence over instance `__dict__` (Ch 6)
**Defensive programming** — making code protect itself from invalid input via error handling, value substitution, assertions (Ch 3)
**Dependency injection** — passing collaborators in (usually via `__init__`) instead of creating them inside (Ch 4, Ch 8)
**Dependency inversion principle (DIP)** — details depend on abstractions, not the reverse (Ch 4)
**Descriptor** — class attribute whose class implements `__get__`/`__set__`/`__delete__`/`__set_name__` (Ch 6)
**Design by Contract (DbC)** — explicit preconditions, postconditions, invariants between caller and supplier (Ch 3)
**Docstring** — documentation embedded in code (`__doc__`); explains, doesn't justify (Ch 1)
**DRY / OAOO** — Don't Repeat Yourself / Once and Only Once: every piece of knowledge defined in one place (Ch 3)
**EAFP / LBYL** — Easier to Ask Forgiveness than Permission vs Look Before You Leap; Python prefers EAFP (Ch 3)
**Equivalence class** — partition of inputs handled identically; one representative test suffices (Ch 8)
**Facade** — single hub hiding many objects; e.g., a package's `__init__.py` (Ch 9)
**`functools.wraps`** — copies name/docstring/annotations onto a wrapper and sets `__wrapped__` (Ch 5)
**Generator** — function with `yield`; lazy, single-pass iterator (Ch 7)
**God object** — class with many unrelated responsibilities (Ch 4)
**Hexagonal architecture** — core defines an API; every external dependency adapts to it (Ch 10)
**Idiom / Pythonic** — language-specific, coded way of doing a task; idiomatic Python = Pythonic (Ch 2)
**Interface segregation principle (ISP)** — prefer small, cohesive interfaces over fat ones (Ch 4)
**Iterator** — object with `__next__` producing values until `StopIteration` (Ch 7)
**KIS** — Keep It Simple: the minimal solution that correctly solves the problem (Ch 3)
**Liskov's substitution principle (LSP)** — subtypes must be usable wherever the parent is; no stricter preconditions, no weaker postconditions (Ch 4)
**MagicMock** — Mock that also supports magic methods (Ch 8)
**Mixin** — base class with reusable behavior, not useful alone, combined via multiple inheritance (Ch 3)
**Monostate** — many ordinary instances with transparently shared state (Ch 9)
**Mutation testing** — introduce mutants into code; a good suite "kills" them (Ch 8)
**Name mangling** — `__attr` becomes `_Class__attr`; collision avoidance, not privacy (Ch 2)
**Non-data descriptor** — descriptor with only `__get__`; instance `__dict__` shadows it (Ch 6)
**Non-redundancy principle** — each precondition is checked by either client or function, never both (Ch 3)
**Null object pattern** — return a domain-typed "empty" object instead of `None` (Ch 4, Ch 9)
**Open/closed principle (OCP)** — open to extension, closed to modification (Ch 4)
**Orthogonality** — changing one component doesn't affect others; side effects stay local (Ch 3, Ch 5)
**Property-based testing** — generate inputs (hypothesis) to find failing cases (Ch 8)
**Refactoring** — changing internal structure without changing external behavior (Ch 8)
**Reification** — turning an implicit domain concept into an explicit object (Ch 3, Ch 9)
**Ripple effect** — a change in one place propagating to distant code (Ch 3)
**Screaming architecture** — code structure reveals what the system does, not the tools it uses (Ch 10)
**Sequence** — object with `__getitem__` and `__len__`; iteration falls back to it (Ch 2, Ch 7)
**`__set_name__`** — hook telling a descriptor the attribute name it was bound to (Ch 6)
**Single responsibility principle (SRP)** — a class has one reason to change (Ch 4)
**`__slots__`** — fixed attribute set; no `__dict__`, less memory (Ch 6)
**Technical debt** — future cost of a compromise made now; grows like interest (Ch 1)
**Template method** — parent's public method holds the algorithm; subclasses fill hooks (Ch 9)
**Test double** — stand-in for a real object in tests (dummy, stub, spy, mock) (Ch 8)
**Type alias** — named type (`Seconds = float`) giving domain meaning (Ch 1)
**Universal decorator** — decorator class with `__get__` so it works on functions and methods (Ch 5)
**Virtual subclass** — type registered into an ABC without inheriting (Ch 4)
**Well-known object** — unique object created once and reused (`None`, `True`) (Ch 9)
**YAGNI** — You Ain't Gonna Need It: don't build for speculative future requirements (Ch 3)
**`yield from`** — delegates to a sub-generator and evaluates to its return value (Ch 7)
